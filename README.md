# פרויקט "השלמת משפטים אוטומטית" (Google Search)

## ארכיטקטורת המערכת - שלב א'

המערכת נועדה לספק השלמה אוטומטית מהירה למשפטים מתוך מאגר טקסטים ענק, תוך תמיכה בשגיאת כתיב אחת לכל היותר (החלפה, הוספה או מחיקה של תו). כדי לעמוד בדרישות הביצועים, המערכת פועלת בארכיטקטורת **Filter and Verify** (סינון ואימות) ומחולקת לשני שלבים עיקריים.

---

### 1. שלב האופליין (הכנת הנתונים)
בשלב זה המערכת מקבלת את מאגר קבצי הטקסט (ה-DATA המקורי) ומעבדת אותם לתוך קבצים בינאריים. 
המידע מחולק ל-2 רכיבים לוגיים מרכזיים (שנשמרים בתוך הקבצים הבינאריים בקידוד UTF-8):

1. **קובץ הטקסט המאוחד (Master Text File)**: במקום לשמור הרבה קבצים ומצביעים, כל הטקסטים המקוריים נאספים לקובץ אחד ענק. אם בשורה במקור היו כמה משפטים, הם מפוצלים כך ש**כל שורה מכילה בדיוק משפט אחד**. היתרון העצום: מספר השורה בקובץ הזה הוא בעצם ה-ID של המשפט! (למשל, ID 17 אומר לגשת ישירות לשורה 17 בקובץ הענק).
2. **טבלת אינדקס N-Grams (זוגות ושלשות)**: כל מילה מהטקסט המקורי מנוקה מסימני פיסוק, הופכת לאותיות קטנות (Lowercase), ומפורקת לכל תתי-המחרוזות באורך 2 (זוגות) ו-3 (שלשות). 
   לכל זוג או שלישייה כזו (למשל `pyt`), יש רשימה של מספרים (IDs). המספרים האלו הם בעצם מספרי השורות בקובץ הטקסט המאוחד!

---

### 2. שלב האונליין (שליפה וחיפוש) - תכנון ארכיטקטורה מפורט

זהו השלב בו אנו מקבלים את הקבצים הבינאריים המוכנים מאנשי האופליין, מחלצים מתוכם את המידע ומגישים את התוצאות למשתמש בזמן אמת. 

#### מבנה הנתונים (Data Models)
**קובץ: `models.py`**
נגדיר את המחלקה בדיוק כפי שהיא מופיעה בדרישות, כדי שנוכל להחזיר אובייקטים מסודרים.
```python
from dataclasses import dataclass

@dataclass
class AutoCompleteData:
    completed_sentence: str # המשפט המלא שהושלם
    source_text: str        # שם קובץ המקור (למשל: file1.txt)
    offset: int             # השורה שבה נמצא המשפט בקובץ
    score: int              # הניקוד שחושב
```

#### טעינת הנתונים מהאופליין (Data Loader)
**קובץ: `data_loader.py`**
מחלקה שכל מטרתה לקרוא את 3 הקבצים הבינאריים (בקידוד UTF-8) ולהחזיק אותם בזיכרון ה-RAM לשליפה מהירה.
**מחלקת `BinaryDataLoader`**:
- **שדה `original_text_db`**: אוביקט גישה לקובץ הטקסט המאוחד הענק (שבו שורה = משפט). במקום לקרוא קבצים שונים, המערכת רק צריכה לגשת למספר השורה (ה-ID) כדי לשלוף את המשפט המלא.
- **שדה `ngram_index`**: מילון (Hash) שהמפתחות שלו הם מחרוזות (של 2 או 3 אותיות) והערכים הם קבוצות (Set) של מספרי שורות (IDs).

#### מנוע החיפוש (Search Engine)
**קובץ: `search_engine.py`**
המחלקה שמנהלת את תהליך ה-Filter and Verify.
**מחלקת `AutoCompleteEngine`**:
1. **פונקציית הניקוי `_clean_query(query)`**: 
   - לוקחת שאילתה כמו `HEY HOW ARE YOU?`
   - הופכת לאותיות קטנות (`hey how are you?`).
   - מוחקת כל מה שהוא לא `a-z`, `0-9` או רווח.
   - תוצאה: `hey how are you`. 
2. **פונקציית יצירת ה-N-grams**:
   - מפרקת את המחרוזת הנקייה לזוגות (Bigrams) ולשלשות (Trigrams).
3. **שלב הסינון - סטטיסטיקה `_get_top_k_candidates`**:
   - עוברת על כל ה-N-grams שניצרנו, ושולפת מה-`ngram_index` את כל ה-IDs.
   - משתמשת ב-`collections.Counter` כדי לספור איזה ID הופיע בהכי הרבה רשימות. 
   - שולפת מפה רשימה של ה-100 IDs המובילים (כדי לא לעשות חישובים כבדים על מיליון משפטים).
4. **פונקציית הליבה `get_best_k_completions(prefix)`**:
   - שולפת את רשימת 100 המועמדים.
   - לכל מזהה (ID) ברשימה, שולפת ישירות את שורה מספר ID מקובץ הטקסט המאוחד (Master File).
   - מעבירה כל משפט לבדיקה מחמירה מול מערכת הניקוד. משפט שחוזר עם 0 (יותר מטעות אחת) - נזרק.
   - ממינת את התוצאות שעברו קודם לפי ציון (בסדר יורד), ובמקרה של שוויון לפי סדר אלפביתי (בסדר עולה). מחזירה את ה-5 הראשונים בלבד.

#### מנגנון הניקוד (Scoring System)
**קובץ: `scoring.py`**
החלק האלגוריתמי המורכב ביותר.
**לוגיקת החישוב המדויקת `calculate_score(query, sentence)`**:
1. מחשבים את **הציון הבסיסי**: 2 נקודות על כל תו חוקי בשאילתה.
2. מבצעים סריקה (Sliding Window) של ה-query על פני ה-sentence כדי למצוא את ההתאמה עם הניקוד המקסימלי (יכולות להיות כמה התאמות במשפט ארוך, אנחנו רוצים את הטובה ביותר).
3. **בדיקת טעויות (עד טעות אחת)**:
   - **מקרה מושלם**: השאילתה מופיעה במדויק בתוך המשפט. מוחזר ניקוד בסיסי שלם.
   - **החלפה (Replacement)**: מורידים 5 נקודות אם הטעות באינדקס 0, 4 באינדקס 1, 3 באינדקס 2, 2 באינדקס 3, ונקודה 1 מאינדקס 4 והלאה.
   - **מחיקה/הוספה (Deletion/Addition)**: מורידים 10 לאינדקס 0, 8 לאינדקס 1, 6 לאינדקס 2, 4 לאינדקס 3, ו-2 מאינדקס 4 והלאה.
   - **יותר מטעות אחת**: מחזירים `0`. (בפייתון, ציון 0 בבדיקה כזו משמעותו "פסול").

**טיפול במקרי קצה (Edge Cases)**:
1. **השאילתה ארוכה מהמשפט המקורי**: תיזרק (אלא אם היא ארוכה ממנו בדיוק בתו אחד והורדה שלו מסדרת הכל).
2. **אותיות גדולות/קטנות וסימני פיסוק**: יטופלו בהצלחה כיוון שההשוואה נעשית רק לאחר שתי המחרוזות נוקו מסימני פיסוק והוקטנו לאותיות קטנות.
3. **רווחים כפולים**: ינוקו או יומרו לרווח יחיד כדי לא לגרום לפסילת משפטים תקינים.
